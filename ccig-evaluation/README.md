# CCIG Evaluation

Evaluates images generated by `ccig-image-generation` against the constraints/prompts
that produced them (`data/ccig_eval_dataset_{SAT,UNSAT}.jsonl`, from `ccig-dataset-gen`).
Four independent, combinable methods:

1. **CLIPScore** — CLIP embedding similarity between image and prompt.
2. **VLM judge** — a vision-language model rates prompt-image alignment 1-5.
3. **Perception** — detect objects, infer their attributes/positions/relations, build
   a scene graph, and check it against the prompt's original ASP constraint with
   clingo (does the *generated* image actually satisfy the logical constraint the
   prompt was built from?).
4. **soft-tifa** — [Soft-TIFA](https://github.com/facebookresearch/GenEval2): a VQA
   model answers each constraint's `subqa` sub-questions (yes/no, true/false, counts,
   property values) about the generated image, scored by the model's own probability
   for the correct answer rather than a hard right/wrong.

This is the last of four pipelines in this repo: `ccig-dataset-gen` (constraints +
prompts) → `ccig-image-generation` (prompts → images) → `ccig-finetuning` (optional
LoRA fine-tuning) → `ccig-evaluation` (images → scores), this one.

## Structure

```
src/
├── common/       # dataset_gen.py (live import of ccig-dataset-gen's domain vocab + clingo solver)
│                 # io.py (match generated images to their prompt records), types.py
├── clipscore/    # CLIPScore
├── judge/        # VLM-judge, closed (API) + open (local) backends
├── perception/   # detect -> region/relation -> attributes -> ASP/clingo scene-graph check
├── soft_tifa/    # Soft-TIFA: VQA sub-question scoring, closed (API) + open (local) backends
└── run.py        # CLI entry point
```

Each submodule has its own `README.md` with more detail.

## Dependency on `ccig-dataset-gen`

Unlike the other pipelines, `ccig-evaluation` imports directly from
`ccig-dataset-gen/src` at runtime (domain color/shape/region vocabulary, and the
clingo solver) rather than duplicating them — see `src/common/README.md`. Both
directories must be checked out as siblings under the same repo root; `dataset_gen.py`
raises immediately at import time if `ccig-dataset-gen` isn't found.

## Setup

```bash
cd ccig-evaluation

# CLIPScore + closed-API judge only
pip install -r requirements.txt

# adds perception (detectors, CLIP attribute classifiers) + local VLM judge
pip install -r requirements-open.txt

export OPENAI_API_KEY=...   # for the gpt-4o judge backend

# clingo must be on PATH (same requirement as ccig-dataset-gen):
# pip install clingo   OR   conda install -c potassco clingo
```

## Run

```bash
python -m src.run \
  --images-dir ../data/generated_images/gpt-image-1 \
  --prompts-file ../data/ccig_eval_dataset_SAT.jsonl \
  --domain clevr \
  --method perception \
  --detector owlv2 --attribute-classifier clip-zero-shot \
  --limit 5

# run multiple methods in one invocation
python -m src.run --images-dir ../data/generated_images/gpt-image-1 \
  --prompts-file ../data/ccig_eval_dataset_SAT.jsonl --domain clevr \
  --method clipscore vlm-judge perception soft-tifa \
  --clip-checkpoint <path-or-hf-repo> --judge-backend gpt-4o --vqa-backend gpt-4o
```

Options:
- `--method` — one or more of `clipscore`, `vlm-judge`, `perception`, `soft-tifa`
- `--domain {clevr,coco}`
- `--out-dir` — default `outputs/<images-dir-name>/`
- `--limit` — cap the number of images processed
- `--clip-checkpoint` — required for `clipscore`; CLIP checkpoint pretrained on `--domain`
- `--judge-backend {gpt-4o,qwen2-vl}` — for `vlm-judge`
- `--detector {grounding-dino,owlv2}`, `--attribute-classifier {clip-zero-shot}` — for `perception`
- `--vqa-backend {gpt-4o,qwen2-vl}` — for `soft-tifa`; needs a dataset with `subqa`
  records (see `src/soft_tifa/README.md` — regenerate via `ccig-dataset-gen` if not)
- `--device {cuda,cpu}` — default: auto-detect

## Output

`outputs/<images-dir-name>/<method>/results.json`, one file per method requested,
keyed by image `id` (see each submodule's README for exact schema).

## Adding a new perception model

- **Detector**: subclass `perception.detectors.base.ObjectDetector`, implement
  `detect(image, class_prompts) -> list[BBox]`, register in
  `perception/detectors/registry.py`.
- **Attribute classifier**: subclass `perception.attributes.base.AttributeClassifier`,
  implement `classify(crop, context=None) -> (label, confidence)`, register in
  `perception/attributes/registry.py`.
- **VLM judge backend**: subclass `judge.base.VLMJudge`, implement
  `judge(image, prompt) -> JudgeVerdict`, register in `judge/registry.py`.
